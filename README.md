# wx-send

**一条命令，把本地文件或图片通过 Windows 微信桌面版发给任意会话。**
会话身份用系统 OCR 双重校验，认不准就中止 —— 宁可不发，也不发错人。

> **One command to send a local file or image to any WeChat conversation on Windows.**
> The chat identity is verified twice via the built-in Windows OCR engine; if it cannot be
> confirmed, the script aborts instead of risking a misdelivery.

```
┌──────────┐   ┌─────────────┐   ┌──────────────┐   ┌──────────────┐
│ 定位微信  │ → │ OCR 校验会话 │ → │ 剪贴板投递文件 │ → │ 回车 + 像素校验│
│ 激活窗口  │   │ 不对就搜索   │   │ CF_HDROP     │   │ 确认已清空    │
└──────────┘   └─────────────┘   └──────────────┘   └──────────────┘
```

## 为什么需要它

在 Windows 上把文件发到微信，常规自动化路子都很脆：

| 做法 | 问题 |
|---|---|
| 点「文件」按钮 → 原生打开对话框 → 填路径 | 对话框焦点、路径含空格、坐标漂移，任一处错就失败 |
| `PostMessage WM_DROPFILES` | 微信 4.x 是 Qt6，走 OLE 拖放，根本不认这个消息 |
| 模拟鼠标点会话列表 | 会话列表顺序会变，必点错 |
| 截图丢给多模态模型判断 | 每次消耗上千 token，慢且不稳定 |

这个脚本换了一条路：**搜索框用 `Ctrl+F` 快捷键唤出（不点坐标）+ 剪贴板 `CF_HDROP` 投放文件（不开对话框）+ 系统 OCR 读标题（不消耗模型 token）**。发送与校验全部在本地完成，对外只输出一行 JSON。

## 快速开始

```powershell
# 1. 直接跑（不需要安装）
pwsh -NoProfile -File .\scripts\wx-send.ps1 -Path "C:\Users\me\Desktop\cat.png"

# 2. 或者装成全局技能，之后任何会话都能调用
pwsh -NoProfile -File .\install.ps1
& "$env:USERPROFILE\.dsh\skills\wx-send\scripts\wx-send.ps1" -Path "C:\a.png"
```

输出：

```json
{"ok":true,"chat":"文件传输助手","verified":true,"sent":true,
 "files":["C:\\a\\b.png"],"ms":8293,"error":null}
```

退出码 `0` 成功 / `1` 失败。典型耗时 **8–15 秒**。

## 参数

| 参数 | 说明 |
|---|---|
| `-Path <string[]>` | 必填。一个或多个文件的绝对（或可解析）路径。图片按图片发，其他按文件发 |
| `-To <string>` | 目标会话显示名，默认 `文件传输助手` |
| `-NoSend` | 只把文件放进输入框，不回车发送（人工检查用） |
| `-NoVerify` | 跳过 OCR 校验（不推荐，仅调试用） |
| `-Force` | 校验失败也继续发送。**会失去「不发错人」的唯一保障** |

> `-Path` 是数组参数。在 pwsh 里写 `-Path @('a.png','b.pdf')`；
> 不要用 `pwsh -File script.ps1 -Path "a","b"` 从外部 shell 传参，那样会被当成一个字符串。

## 返回字段

| 字段 | 含义 |
|---|---|
| `ok` | 整体成功 |
| `chat` | 目标会话名 |
| `verified` | 会话标题经 OCR 校验与 `-To` 一致 |
| `sent` | 回车后输入框已清空（消息已发出） |
| `files` | 实际发送的文件绝对路径 |
| `ms` | 耗时（毫秒） |
| `error` | 失败原因（中文，可直接转述） |
| `ocr` | 失败时附上 OCR 读到的原始标题，便于排查 |

## 工作原理

1. **定位窗口** —— 遍历顶层窗口，取类名匹配 `Qt*QWindowIcon`、面积最大的那个。找不到就按桌面快捷方式 / 注册表 `Uninstall` 键定位 `Weixin.exe` 启动，必要时点「进入微信」。
2. **校验会话** —— 截图聊天标题区 → 交给 `Windows.Media.Ocr`（经 `wx-ocr.ps1`）→ 与目标名做**字符重合度**比对。OCR 会认错字（「文件传输助手」常被读成「文 俐 专 输 助 手」），所以按命中字符比例打分：名字 >4 字要求 ≥50%，≤4 字要求 ≥75%，≤3 字要求全中。
3. **切换会话** —— 不匹配则 `Ctrl+F` 唤出搜索框（**纯快捷键，不依赖坐标**）→ 粘贴会话名 → 回车 → 再校验一次。
4. **投放文件** —— 把文件写进剪贴板 `CF_HDROP` → 点输入框 → `Ctrl+V`。微信把文件变成待发送附件。
5. **发送与确认** —— 回车 → 比较发送前后输入框区域的像素差，确认已清空。

任一步不到位就退出，不发送。

## 安全设计

**发错人的代价远大于发送失败**，所以脚本在「确认身份」上是保守的：

- 校验不过 → 中止，退出码 1，`sent:false`
- 中止前按 `Esc` 收起搜索浮层，避免把会话名当文字消息发出去
- 剪贴板只放文件，不放文本；不会顺手发一条消息出去
- `-Force` 是唯一的旁路，默认不用

已测场景（Windows 11 / 微信 4.x / 120DPI）：

| 场景 | 结果 |
|---|---|
| 已在目标会话，发单个文件 | ✅ 8.2s |
| 当前在别的会话，发文件 | ✅ 14.2s，自动搜索切换，原会话未收到任何消息 |
| 一次发图片 + 文本两个 | ✅ 8.4s |
| 会话名不存在 | ✅ 正确中止，未发出任何内容 |

## 环境要求

- Windows 10 / 11
- 微信桌面版 4.x（Qt6），已登录，窗口可最小化
- PowerShell 7（推荐）或 5.1
- 系统中文 OCR 语言包（中文版 Windows 默认自带）

## 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| `Ctrl+F 没有唤出微信搜索框` | 微信不在前台（全屏程序盖住）或窗口卡死；点一下微信再跑 |
| `无法确认已打开会话` | 会话名写错，或搜索结果第一项不是目标。先手动打开一次 |
| `输入框未出现附件` | 输入框没拿到焦点，重试一次通常就好 |
| `剪贴板文件列表异常` | 别的程序占着剪贴板，关掉剪贴板管理器 |
| `微信窗口未出现` | 微信没登录，手动登录后重跑 |
| 换了高缩放比的机器后坐标偏 | 见下方「缩放」 |

### 缩放

脚本里的版面常量按「微信 UI 1:1 物理像素渲染」写死（开发机 120 DPI 实测）。若目标机器的系统缩放是 150% / 200%，微信 UI 在物理像素上会等比放大，标题区与输入框坐标随之偏移。症状是 `verified:false` 并报「Ctrl+F 没有唤出搜索框」或「输入框未出现附件」。

修法：把 `wx-send.ps1` 顶部的 `$headerX`、`$headerY`、`$inputCrop*`、`$clickCands` 常量乘以缩放比（`系统缩放 × 100`），或把系统缩放调回 100% / 125%。

## 作为 Agent 技能使用

`SKILL.md` 是给 AI 助手看的技能说明（Claude Skill / DSH Skill 格式，YAML frontmatter + 使用说明）。
装到 `%USERPROFILE%\.dsh\skills\wx-send\` 后，任何会话都能识别「用微信发给我」这类请求并直接调用脚本。

换机器时把整个目录复制过去，跑一次 `install.ps1` 即可（它会修 UTF-8 BOM、做自检）。

## 已知限制

- 只支持 Windows（依赖 Win32 + `Windows.Media.Ocr`）
- 一次调用对应一个会话；批量发多个会话需要多次调用
- 微信弹广告窗口 / 登录失效时需要人工处理一次
- OCR 质量依赖系统语言包，非中文系统读中文标题成功率会下降
